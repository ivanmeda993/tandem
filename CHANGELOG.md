# Changelog

## 0.1.0

First version.

- Claude Code mod: Tandem panel, status band, Codex answer cards, the `/tandem` command, and the `send`, `connect`, `start_codex`, `threads` and `ask_thread` tools. Codex's answers wake an idle Claude session.
- The orchestrator: `/tandem orchestrate <goal>` has Claude ask how to organize the work, plan tasks with roles and review them. Tandem runs a Codex worker per task in its own git worktree and named thread, gathers the reports into one digest, sends review notes back as the worker's next turn, has a fresh simplifier propose up to 10 simplifications of approved code that the user picks and the task's worker applies, and merges approved work into the run's branch `tandem/<name>/result` (each task works on `tandem/<name>/<task>`, named for the run's goal): on its own by default (`auto_merge`), or when the user clicks Merge with it off. The user approves the plan and merges the run's branch into theirs; parallel workers, their effort and access, fix rounds and a budget are set per run. By default workers run like regular Codex threads (full access, so tools that write such as Figma work); their threads stay at the project root, so the Codex app lists them with the project, and each message names the task's worktree to work in. Codex can orchestrate too: a run started from a Codex thread gets a conductor that sends each update into that thread, and Codex asks the user there before every decision that is theirs.
- Claude can start a new Codex thread (named, with its own model and reasoning effort, optionally in its own git worktree), and Codex can start a new Claude Code session in the background that joins its thread (`tandem new-claude`, with only Tandem's `connect` and `send` tools pre-approved). Agents that Tandem starts cannot start more agents.
- The orchestrator keeps short notes of what the run's state does not hold (`orch_note`, `tandem orch note`); when its conversation is compacted, resumed or cleared, Tandem hands it the run's state, latest events, its notes and the workflow again (`tandem orch journal`). Cleaning up a finished run removes the notes.
- Review: Codex reviews a pull request, a branch, a commit or the uncommitted changes in a read-only thread (a pull request's code in a detached worktree, with its description and CI checks): the bugs the change introduces, how it fits the codebase, tests, security, performance and missing follow-through, each finding with a priority, its lines and a confidence, and a verdict. Claude checks each finding in the code before telling the user; the panel shows the findings, and the user posts the ones they pick to the pull request as one review after confirming. The orchestrator's reviewer and the reviewer role check the same things.
- Codex skills: `tandem` (answer Claude, start a conversation, start Claude, work as an orchestrated worker) and `ask-claude` (second opinion from Claude, read-only by default).
- Core script with rooms per project: delivery through `codex queue` when a Codex app has the thread open, otherwise a turn Tandem runs itself through a short-lived `codex app-server` (one at a time per room, failures reported back), so the threads it starts show in the Codex app; answers matched to the Codex turn that handled them, Claude joining the room Codex opened for a thread, one listener per room, a message limit that only the person raises, and `threads`, `ask-thread`, `orch` and `doctor` commands. Turns of a room run in the order they were sent; a room stays with its thread; a review, a read-only role or a sandboxed worker is never handed to a Codex app or CLI that would run it with its own settings; a review target, base or refspec that reads as a git option is refused, as is a pull request link of another repository; and `ask-thread` sends its question on stdin and switches off the MCP servers of the project's `.codex/config.toml` too.
- Workers and new threads open in the Codex app by default (in the background, named "<project> · <task>"), so the user watches them and writes to them there; turns that need Tandem's own settings (read-only roles, the simplifier's output schema, sandboxed runs) run in the background. The panel shows each working agent with a spinner and the last step it took (marked ⚠ after 8 minutes with no new step), every task of a plan in full, and the simplifier's proposals whole with their exact change. It lists tasks by who has them with finished ones folded into one row, meters worker turns and the Codex usage limit in the run's header (offering 10 more worker turns once they run low, which the orchestrator hears of at once), has keys for its main decisions, and notifies the person on their Mac when a run has waited for them for 20 seconds; the band above the prompt names what waits. Merge says what it does (the run's branch, by name; the tasks waiting for it), shows a summary of each task on request (its worker's report, the reviewer's notes, the files it changed) with a button to the worker's chat in the Codex app, and tells the orchestrator at once, and a run's header names the branch its merged work collects on and explains a run's steps on request.
- Runs hold up when things go wrong: a worker whose runner dies fails instead of staying "running"; a report a cut-short poll already read is recovered from the room's log; an interrupted start is picked up instead of orphaned; stopping or cancelling a worker stops it (a turn in the Codex app waits as "stopping"); conflicts go back to the worker that made the change without using a fix round; merges skip the project's git hooks and show git's own errors; a task waits for unmerged work on the same paths; and an out-of-budget review pauses the run so the panel offers more. A Codex orchestrator's updates are retried until they arrive. Clean up names the workers' threads the Codex app still has open, with a button to open each there, and archives them on a later Clean up once the app lets them go. A simplifier that fails or is stopped leaves the approved change as it is, ready to merge; a failed task waits in the panel, where the user can cancel it; a stopped run is still read until a worker's turn in the Codex app ends; approving takes only the tasks the panel showed; after a merge conflict a task's diff is its own work, against the run's branch; and two tasks that own the same path in two spellings (`./src`, `src/`, `Src`) wait for each other.
- The panel has three tabs (Orchestrate, Codex chat, Archived): Codex threads can be archived and restored from it (a running Codex app's list follows at once, as it does for Clean up), a thread with no name shows its first words, and the band above the prompt shows a run's progress and the last step a worker took. While Codex works for a session, a small background watcher agent keeps the session marked as running in the Claude app's sidebar; when it stops, the line Claude Code shows says why. A session whose folder was moved or removed follows it, or says that the folder is gone. Disconnect holds: a connect that was still on its way cannot undo it, and the panel closes a room it leaves. A poll, a status or a connect still on its way never lands in the conversation or run the panel moved on to; Merge has a row of its own and Merge all merges each task once; text the panel passes to the core may start with a dash; and the orchestrator's tools leave a run the session only watches alone and cannot stop a whole run.
